SHADOW OF DEATH WEBSITE

Setup guide — from "runs on my PC" to "live on the internet", free

What's built: a forum-style community site with sign-up and login, forums (categories, threads, replies, quotes, pinned and locked threads, staff tools), public posts (a community feed plus a wall on every profile, with likes and comments), friends (requests, accept, remove), and a Facebook-style chat bar at the bottom of the screen: friends list with online dots and chat windows where messages appear instantly, with a "typing…" note and a sound. There's also a Messages page (an RSPS-style inbox) with every conversation.

1. Try it on your PC (no setup needed)

  1. Open the folder Shadow of Death Website and double-click Preview website.bat.
  2. Your browser opens http://localhost:8085. A black window stays open; closing it stops the preview.
  3. The site starts in DEMO MODE (yellow stripe at the top). Fake accounts, posts and messages are saved only in your own browser.
  4. Log in as Shadow (owner) or Kagemaru (admin), password demo123, or register a new account.
  5. Test the chat: open a second browser tab, log in as the other account, and message each other from the chat bar. ShadowBot is always online and answers you too.
  6. Settings → Reset demo wipes the demo data.

Nobody else can see the preview; it only runs on this PC and opens no ports.

2. Why Supabase (the free "brain" behind the site)

GitHub Pages hosts the site for free, but it can only serve files: it can't store accounts, posts or chat. Supabase is a free service that gives the site real accounts (sign-up, login, password reset), a database for posts and messages, and live updates so chat messages and "who's online" appear instantly.

Free plan gives you (roughly)Good to know
Up to 50,000 active users a month, a 500 MB database, live chat connections for a couple hundred people at once Far more than the server needs for a long time. No card needed.
Accounts, passwords and emails stored safely by Supabase The site never sees passwords. Security rules in the database decide who can read and write what.
Projects that nobody uses for 7 days get paused Once people use the site this won't happen. If it does, press Restore in the Supabase dashboard.

Moving to a paid domain or host later doesn't change any of this: the same Supabase project keeps working from any address.

3. Create the Supabase project YOU

You create the account yourself (Claude can't make accounts or type passwords for you).
  1. Go to supabase.com and click Start your project.
  2. Choose Continue with GitHub and sign in with your GitHub account (tjsmith95). That way there's one less password.
  3. If it asks for an organization, call it Shadow of Death and pick the Free plan.
  4. Click New project:
    • Name: shadow-of-death
    • Database password: click Generate a password and save it somewhere safe (you'll rarely need it).
    • Region: the one closest to you (for Texas pick an East US or Central US option).
  5. Click Create new project and wait a minute or two while it sets up.

4. Set up the database YOU

  1. In the Supabase dashboard, open SQL Editor in the left menu and click New query (or the +).
  2. On your PC, open Shadow of Death Website\supabase\schema.sql with Notepad, press Ctrl+A, then Ctrl+C.
  3. Click into the SQL Editor, paste (Ctrl+V) and click Run.
  4. You should see "Success. No rows returned". If Supabase shows a warning about "destructive operations", click to run it anyway: the file only replaces its own rules, never your data.

This makes the tables (profiles, forums, posts, likes, comments, friends, messages), the security rules, the anti-spam limits, the 13 starting forums and switches on live updates for chat.

5. Sign-up settings YOU

  1. Left menu → Authentication → Sign In / Providers (sometimes just Providers) → Email.
  2. Turn Confirm email OFF and click Save.
    Why: Supabase's built-in email sender only delivers to your own team's addresses, so players would never get the confirmation email and couldn't finish signing up. With it off, players can log in straight after registering. Later we can add a free email sender (for example Resend) so confirmation and "forgot password" emails reach everyone. Until then, Forgot password only works for your own email.
  3. Go to Authentication → URL Configuration:
    • Site URL: https://playshadowofdeath.github.io/ (the address from step 7)
    • Redirect URLs → Add URL: https://playshadowofdeath.github.io/** and http://localhost:8085/**

6. Connect the site to Supabase YOU

  1. In Supabase, click the Connect button at the top (or Project Settings → API Keys / Data API).
  2. Copy the Project URL (looks like https://abcdefgh.supabase.co).
  3. Copy the public key: called publishable (starts with sb_publishable_) or anon public (a long key starting with eyJ). Either works.
  4. Open Shadow of Death Website\js\config.js in Notepad and paste them between the quotes: 
    supabaseUrl: 'https://abcdefgh.supabase.co',
supabaseAnonKey: 'sb_publishable_xxxxxxxxxxxx',
  5. Save, then run Preview website.bat again. The yellow DEMO stripe is gone and the site is now using the real database.
Never paste the secret / service_role key into the site. That one can do anything and must stay private. The public key is meant to be public: the database's security rules keep people from editing other people's things.

Make yourself the owner

  1. Register your account on the site (for example Shadow).
  2. In Supabase → SQL Editor → New query, paste this and click Run: 
    update public.profiles set role = 'owner' where username = 'Shadow';
  3. Refresh the site. You now get the red Owner badge, can pin, lock and delete threads, ban members, and set other people's rank from their profile page (Member, Moderator, Admin, Owner).

7. Put it on the internet with GitHub Pages YOU

This gives the site the free address https://playshadowofdeath.github.io/.

  1. Make the free organization: github.com/account/organizations/new?plan=free. Organization name playshadowofdeath, your email, "My personal account" (tjsmith95). Skip inviting people.
  2. On github.com/new set Owner to playshadowofdeath, name the repository exactly playshadowofdeath.github.io, set it to Public, and click Create repository.
  3. On the new repo's page click uploading an existing file.
  4. Open the Shadow of Death Website folder, select everything inside it (Ctrl+A; not the folder itself) and drag it onto the GitHub page. Wait for the uploads to finish, then click Commit changes.
  5. Go to the repo's Settings → Pages. Under Build and deployment pick Deploy from a branch, branch main, folder / (root), and click Save.
  6. After a minute or two, https://playshadowofdeath.github.io/ is live. Share it with your players!

The installer stays where it is (the Shadow-of-Death repo's Releases); the site's Play now button links to it. To update the site later, upload the changed files the same way (GitHub replaces the old ones).

Moving to your own domain or a paid host later

  • Own domain (about $10–15 a year, e.g. shadowofdeath.com): GitHub repo → Settings → Pages → Custom domain, then add the records GitHub shows at your domain seller.
  • Paid host / the Contabo VPS: copy the same folder there. Nothing needs rewriting: every link is relative and all pages work from any address.
  • Either way, update the Site URL and Redirect URLs in step 5 to the new address.

Coming later: game account link

Accounts are already built for it. When the server moves to the VPS, the game server will make a forum account automatically when someone registers in-game (status "incomplete", linked to their game name). They then log in on the site with their game name and password and see Finish your sign-up, where they add their email. That needs the secret Supabase key on the game server only (never in the website), so it waits for the VPS.
